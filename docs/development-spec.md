# 接口工坊 IfaceForge

开发规格与验收基线 · v1.1 · 2026 年 11 月 16 日（香港时间）

## 1. 名称和目标

| 用途 | 名称 |
| --- | --- |
| 中文产品名 | 接口工坊 |
| 英文产品名 | IfaceForge |
| 开源仓库名 | `ifaceforge` |
| CLI 命令名 | `ifg` |
| 项目配置文件 | `.ifaceforge.json` |
| 默认安装和数据目录 | `.devtools/ifaceforge/` |

开发者在任意 Git 项目中启动工具，即可查看 HTTP API、MCP 服务和工具，以及仓库中用 `SKILL.md` 编写的技能。API 和 MCP 能在界面或 CLI 中调试、保存用例、运行测试。技能可搜索和查看。三类内容都能生成离线 Wiki。中文界面使用“接口工坊”，英文界面使用“IfaceForge”。

工具按单个项目运行在本机，自动使用属于自己的 SQLite 文件。开发者和 AI 可以用完整 CLI 操作本项目。默认提供简体中文和英文界面。标准入口适用于各语言项目，源码识别能力以已交付的适配器为准。

## 2. 首版边界

本文件是首版的功能、实现及验收基线，确认后放入未来的独立仓库。仓库中的 `AGENTS.md` 指向它。开发者和开发代理按下表的需求编号工作。新增模块、协议、支持平台、公开命令、数据采集或外部依赖前，先核实属于哪个编号。能够在该编号下解释的具体实现可直接调整。需要改变可见行为或支持范围时，提交一份说明，等所有者确认并更新规格后实现。

首版一次性完成 R01–R11 并统一交付。按最短路径实现所有既定功能，优先复用现有库和共用逻辑，局部完成后直接接续，免除分期交付和阶段性评审。对正常使用中的阻塞及时修复。超出范围的建议和非阻塞优化可记录，留待首版之后处理。

## 3. 启动、文件和项目识别

### 3.1 运行契约

- 首版验收 Windows x64、macOS arm64 和 Linux x64。以 Node.js 26 LTS 和 Git 为首选运行环境，保留 Node.js 24 LTS 兼容基线。发布说明锁定实际验证过的补丁版本。可用已安装 Node 启动源码版或解压版。Windows 支持 PowerShell，macOS 与 Linux 支持常用 POSIX Shell。发布包包含已构建资源和离线运行所需的应用依赖，由用户已有的 Node.js 启动。
- 关键入口 `ifg start|status|stop`。可指定 `--project <路径>`。不指定时通过当前目录向上解析最近的 Git 工作树根。目录来自真实路径，支持中文和空格。无法识别项目时直接返回错误及示例。Git worktree 使用各自根目录和数据地址。
- `start` 默认后台启动并打开浏览器。自动化用 `--no-open`。默认绑定 `127.0.0.1` 的可用端口。可用 `--port` 指定端口，显式端口被占用则报错。返回实际 URL 和组件版本。需要前台运行时使用 `--foreground`，标准输出约定见 CLI 节。
- 同一项目只启动一个 Web 服务。启动前查看实例记录，再向本机状态接口验证实例指纹。失效记录在确认服务找不到后清理。停止只向匹配该项目和实例凭证的工具进程发出请求，回收本次启动的 MCP 子进程。
- `status` 返回数据库路径、Web 是否运行、实际监听地址及各组件版本。普通 CLI 命令直接操作当前项目数据，无需 Web 服务或浏览器。

~~~text
project/
  .ifaceforge.json                       可选项目配置
  .devtools/ifaceforge/
    app/                             工具源码或解压包
    data/
      workbench.sqlite
      instance.json                  本地实例信息
      logs/
      wiki/                          默认生成目录
      wiki-notes/                    人工补充说明
~~~

工具目录可由 Git 的本地排除机制或项目现有规则忽略。脚本不自动修改外层项目的 Git 配置、锁文件和构建链。升级只替换应用目录，SQLite 随版本迁移，旧数据留存。首次运行数据库访问失败时显示路径和原因。

### 3.2 项目配置契约

- `.ifaceforge.json` 可随项目签入，JSON Schema 版本为 1。字段限定为 `schemaVersion`、`sources` 和 `exclude`。源字段为 `id`、`roots`、`adapters`、`openapi`、`mcpConfigs`。`schemaVersion` 必填，其余采用空数组或默认发现。源 `id` 必填，其余可省略。路径相对仓库根。未知字段、重复 ID、重复键、越界路径和类型错误返回可定位诊断。项目无配置时可立即用默认扫描。
- 本机数据库另存语言、环境、MCP 连接及扫描选项。扫描选项在本机有显式覆盖时优先，否则读项目配置。运行时取值按本机所选环境的普通变量、进程可用变量或本机设置的密钥引用解析。请求文件中的 `inputs` 最终在运行前绑定。秘密值优先走本机环境变量，找不到时报告变量名。
- 配置发现不会自动连网、安装依赖、导入应用模块或执行启动命令。项目可提供启动模板，实际连接时由用户在 UI 点连接或用 CLI 显式执行连接命令。目标运行时仍按该项目自身的启动说明准备。

~~~json
{
  "schemaVersion": 1,
  "sources": [
    {
      "id": "task-api",
      "roots": ["apps/api"],
      "adapters": ["express"],
      "openapi": ["apps/api/openapi.yaml"],
      "mcpConfigs": []
    }
  ],
  "exclude": ["**/generated/**"]
}
~~~

## 4. 实现结构和数据

### 4.1 工程选型

单个 TypeScript 项目、单个 `package-lock.json`。前端 React、Vite、Ant Design，构建后由本地服务提供。HTTP 路由可用 Express，使用 Node 提供的 HTTP 能力执行请求。SQLite 用 Node.js LTS 的 `node:sqlite`，以支持矩阵实际通过的补丁版本为基线。MCP 客户端和样例使用已发布的官方 TypeScript SDK，两种传输的支持见第 7 节。Git 操作用参数列表直接调用本机 Git。测试以 Vitest 和 Playwright 为基线。开工锁定依赖及版本。 [Node.js 26 SQLite 接口](https://nodejs.org/download/release/v26.13.1/docs/api/sqlite.html) · [MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/)

~~~text
src/
  cli/          参数解析、输出和 CLI 退出码
  server/       回环 HTTP、UI 静态资源和实例启动
  app/          扫描、目录、执行、Wiki、数据维护共用入口
  scanner/      文件与标准解析，框架适配器
  protocols/   HTTP、MCP 连接和执行
  storage/     SQLite、迁移、附件和实例路径
  web/         Ant Design 页面和中英文资源
  schemas/      公共 JSON Schema
fixtures/      Express、FastAPI、MCP 与技能样例
tests/         单元、协议集成、CLI 和 UI 端到端
docs/          使用、开发、适配、发布与本规格
~~~

CLI 和 Web 都调用 `app/` 中的相同函数，避免行为和错误码分叉。Web 中的长任务通过本地状态和有限轮询回读。CLI 默认等待执行结束，用户可 Ctrl+C，工具保存已完成步骤。配套进程仅用于 Web、MCP 子进程和可选的后台扫描工作。SQLite 事务只覆盖读写，协议请求在事务外执行。

### 4.2 SQLite 持久化

| 表或存储项 | 最小数据 |
| --- | --- |
| `settings`、`profiles` | 设置键、语言、扫描配置、环境、变量引用、API 和 MCP 目标定义 |
| `scans`、`scan_files` | 扫描编号、状态、Git 提交、工作树摘要、范围、适配器版本、文件摘要和诊断 |
| `entities`、`observations` | 能力编号、类型、服务、原始名称、说明、接口结构、证据来源、位置和内容摘要 |
| `cases`、`suites` | 稳定编号、名称、版本、请求模板、步骤、断言和输出提取规则 |
| `runs`、`run_steps` | 任务编号、用例版本、环境摘要、状态、耗时、脱敏后的请求响应、错误与附件相对路径 |
| `wiki_exports` | 导出编号、扫描编号、输出目录、语言、清单摘要和状态 |

存时间统一用 UTC ISO 8601，界面按本机时区显示。外键和唯一键约束由 SQLite 执行。库结构使用递增版本和事务迁移。并发写入使用有界等待。发生冲突时报告 `BUSY`，写盘失败时保留此前已提交内容。目录扫描生成新快照，完成前当前目录仍用旧结果。不完整扫描的诊断单独保存。UI 和 CLI 同时编辑用例时用版本号检测旧数据覆盖风险。

本机密钥值只在运行时注入。日志、报告、Wiki 和导出用例剔除认证 Header 及已解析秘密值。响应预览保留有界正文和截断标记。历史清理只删除工作台受管历史及其附件。备份导出含 SQLite 一致副本和被引用的受管文件，经格式及路径校验后恢复。恢复覆盖指定项目数据，执行前显示来源；CLI 用显式 `--replace`，Web 用本机确认框。数据库未初始化的空项目可直接恢复。

### 4.3 本机边界

Web 只绑定回环地址并检查 Host。浏览器发起写操作或执行命令时使用同源检查和页面内生成的随机请求凭证，作为防止其他网页触发本机操作的措施。应用代码不启用跨域。CLI 无需登录。MCP stdio 使用可执行文件与参数数组，直接启动且工作目录明确。仓库 Markdown、工具输出和文件名按不可信文本渲染。源码和引用打开限制在当前项目内，经真实路径核对，Wiki 写入默认落在工具目录或用户指定目录。

## 5. 扫描、合并与搜索

### 5.1 扫描流程

1. 用 Git 枚举跟踪文件，按需要包含未跟踪且未忽略的文件。依据根目录与排除规则过滤。跳过 Git 元数据、依赖、构建输出、工具自身数据及越界符号链接。按需扫描，首启 UI 触发一次。
2. 检测 OpenAPI 内容、受支持的 MCP 配置及 `SKILL.md`。源码适配支持 FastAPI 普通路由装饰器、Express 静态路由、MCP TypeScript SDK 中使用字符串常量名称的工具注册。适配器文档列出实际支持的语法。
3. 通过文件摘要和配置版本复用未变化结果。全扫可重新构建目录。程序缺少依赖、遇到语法解析失败或动态拼装时输出诊断，源记录保留在快照。
4. 将运行发现独立挂到目标环境。HTTP 运行发现通过导入指定 OpenAPI URL 完成，源码适配也可使用机器可读路由清单。MCP 运行发现由连接后的枚举完成，逐页记录并区分未公布、空集合、权限不足、不可达及故障。
5. 根据稳定 ID 对齐声明、静态实现和运行观察。版本号由规范化定义内容摘要决定，并保留原始定义。相同输入的 CLI 与 UI 得到同一批记录。切换项目时只使用新项目的配置与库。

| 类型 | 稳定键 | 首版支持 |
| --- | --- | --- |
| API | 服务 ID、方法、规范化路径模板 | OAS 3.0/3.1 JSON、YAML。路径参数名保留显示并独立对比。保留媒体类型、认证说明、参数和响应。支持项目内的相对引用 |
| MCP | 服务 ID、类型、协议中的名称或 URI | `.mcp.json` 或项目显式指定的同结构 JSON，读取 `mcpServers` 下的命令或 URL、参数、变量引用。运行支持工具、资源、资源模板、提示词 |
| 技能 | 项目相对路径、技能名称 | `SKILL.md` 的 YAML 头部及正文。收录通过 Markdown 相对路径声明的项目内引用，并展示缺失引用 |

源码位置须提供相对路径及能够准确获得的行号。只知道路径时显示路径。原始和业务字段均以数据处理。首版不执行网络 `$ref`，项目外引用和循环标记为未解析。对比同类来源及同环境版本。动态注册、未知语法和权限过滤列出原因。只有完整且范围一致的快照才报告已消失的观察，不完整扫描不直接移除旧结果。

### 5.2 目录行为

目录以名称、ID、摘要、路径和正文匹配搜索。查询支持对象类型、服务、来源、发现状态筛选，以及分页。名称精确匹配优先，其余按名称及相对路径稳定排序。空关键词展示目录。列表显示声明、源码、运行等证据；详情列出全部来源、字段差异和原始文件。报告四类差异，分别是实现缺少契约、声明没有可核对的实现、运行未发现及定义冲突。不显示无法确定分母的覆盖率。

源码扫描适配器使用固定输入输出模型，贡献者增加一个适配器及测试样本即可接入。首版以源码合并方式安装新增适配器。项目不上传脚本到工具内执行。MCP SDK 解析能力以服务端实际发现优先，静态发现用于说明来源。

## 6. HTTP API 功能

### 6.1 请求和响应

- 从已发现操作生成草稿，也可手动创建。请求包括方法、绝对 URL 或环境地址加路径模板、查询项、Header、正文和超时。支持常用 HTTP 方法、JSON、纯文本、表单编码和无正文。查询项与 Header 可重复，选填项只有启用时才发送。相对路径和查询参数分别编码，执行前展示实际目标。
- 认证使用 Header 和变量引用，支持常见 Bearer/Basic/API Key 配置。Basic 由明确的用户名和密码变量构造。单次请求仅访问所填目标。首版将 HTTP 3xx 响应原样返回，使用者可以显式访问重定向地址。
- 结果显示状态、耗时、响应 Header、JSON/文本或二进制类型、截断标记和错误。接到 4xx 或 5xx 仍是收到 HTTP 响应，用例可断言这些结果。可复制脱敏的 cURL 草稿。响应在解析、网络、超时和断言层各有可区分错误。
- Schema 校验使用适配 OAS 3.0 和 3.1 的规范解析。以实际状态和响应的媒体类型选定义，依次匹配精确状态、范围码和 default。定义缺失或不支持时，断言显示“无可用定义”，测试报告保留原因。可只运行状态码等已有断言。OpenAPI 片段导出保留依赖的项目内引用或生成自含子集，输出格式 JSON 或 YAML。

支持的入口为仓库中的 OpenAPI 文件、明确输入的开发服务 URL，以及手工草稿。读取 OpenAPI URL 的访问参数来自所选环境。响应正文过大时显示截断，无法完整获取的响应不会被当作一次完整 Schema 通过。 [OpenAPI](https://spec.openapis.org/oas/)

## 7. MCP 功能

| 连接 | 行为 |
| --- | --- |
| `stdio` | 以命令、参数数组、工作目录、明确的环境变量引用启动。UI 连接显示完整启动配置，点击后执行。CLI 显式调用连接或执行命令时启动。协议与 stderr 分开，关闭连接后回收本次启动的进程 |
| Streamable HTTP | 使用明确 URL 和可配置 Header，按实际协议版协商。显示服务信息、协议版本、错误和进度。套件逐步共享同一客户端连接，协议级状态按所选版本处理 |

首版两种传输均测试 MCP 2025-11-25 和 2026-07-28 的发现与基础调用。SDK v2 优先使用。遇到旧修订由 SDK 提供的兼容层处理，安装前在公开样例里验证实际行为。首版范围是规范中的核心方法和上表两种传输，其他扩展或旧式独立 HTTP+SSE 由需求变更决定。 [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25) · [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28) · [SDK 版本说明](https://ts.sdk.modelcontextprotocol.io/v2/)

1. **发现**使用工具、资源、资源模板和提示词列表方法。处理分页，在游标重复或中断时显示未完成。来源落到所选连接和以安全方式记录的环境别名。列表刷新由用户发起。
2. **调用**在工具详情根据对象 Schema 展示基础字段。复杂结构使用 JSON 编辑。执行前校验认为可支持的参数规则。显示 JSON-RPC 错误、工具 `isError`、结构化结果、内容列表及任务引用。
3. **资源与提示词**支持列举、读取 URI 资源和获取提示词；资源模板展示参数，由用户填 URI 再读取。文档和浏览器安全预览只显示被支持的文本或元数据。服务请求额外用户交互、模型采样及其他首版之外能力时明确返回不支持。
4. **连续执行**本机一个 UI 会话、一个 CLI 批次，或一个测试套件可复用同一 stdio 进程。独立 CLI 命令结束时关闭该命令建立的会话。首版用批次或套件提供跨步骤状态，不要求在多个 CLI 进程之间共享子进程。
5. **失败恢复**客户端超时或中断后记录最后已知阶段。有可查询的原任务引用时保留原引用供后续检查。连接断开和进程退出有独立错误。发出去且结果无法确认的调用标为“结果待查”，工具不自动重发。新调用由用户发起。

## 8. 技能

技能页展示名称、简介、正文、所在目录、来源、可选头部字段及引用。按名称、简介、路径或正文搜索，大小写及 Unicode 处理和统一目录一致。渲染 Markdown 目录，支持查看原文、复制路径和打开项目内引用。正文较长时分区显示。缺少必填头部、名称不合适或引用不存在时保留可查看记录并显示提示。链接预览限制在项目范围，外部链接可显示原地址。技能脚本仅作为项目文件引用。 [Agent Skills 规范](https://agentskills.io/specification)

## 9. 调试与测试数据

### 9.1 用例与套件

用例为版本化 JSON，支持从 UI 草稿保存、CLI 导入导出及重跑。字段为 `schemaVersion`、`id`、`name`、`kind`、`profile`、`request`、`assertions`、`extract`。HTTP 与 MCP 请求字段由类型区分。导入先验证整个文件，再写库。重复 ID 内容相同可复用，内容不同时显式指定 `--replace`，UI 显示差异。用例编辑每次增加版本。执行记录固定当次内容摘要，后续编辑不会改变既有报告。

套件为一列现有用例 ID 和按用例声明的输出变量映射。按顺序执行，默认失败后停止，剩余项标“跳过”。同一个 MCP 连接配置在同套件内复用。用例只可用先前已经提取的变量。环境变量、输入和上步输出通过固定引用符号解析，无命令或脚本求值。引用对象或数组时保持原 JSON 类型。字符串中只允许把标量插入文本。提取位置采用 JSON Pointer。 [JSON Pointer 标准](https://www.rfc-editor.org/rfc/rfc6901)

| 目标 | 支持的断言 |
| --- | --- |
| HTTP | 期望状态码、字段存在及等值、符合已选响应 Schema |
| MCP | 可发现工具、期望工具成功或返回业务错误、结构化字段存在及等值、项目内指定文件存在 |
| 公共 | 比较失败显示实际值、预期值及具体检查。秘密按变量名识别并掩码 |

~~~json
{
  "schemaVersion": 1,
  "id": "get-task",
  "name": "读取样例任务",
  "kind": "http",
  "profile": "demo",
  "request": {"method": "GET", "path": "/tasks/42"},
  "assertions": [
    {"type": "status", "equals": 200},
    {"type": "jsonEquals", "pointer": "/id", "equals": 42}
  ],
  "extract": {"taskId": "/id"}
}
~~~

HTTP 变量引用使用 `{{name}}`。MCP `request` 的必填字段为 `tool` 与 `arguments`，资源、提示词由临时调用入口访问。套件 JSON 包含 `schemaVersion`、`id`、`name`、`caseIds`。不可读取的配置、无效变量、重复 ID 或版本冲突通过错误码返回。字段说明与示例公开为 CLI 可读取的 Schema。

| 实施契约 | 具体字段和约束 |
| --- | --- |
| 本机设置 | `schemaVersion`、`locale`、可选 `scan` 覆盖项。`locale` 取 `zh-CN` 或 `en`。`config apply` 只能写本机库 |
| 环境和连接 | `schemaVersion`、`id`、`name`、`variables`、可选 `http`、可选 `mcp`。连接定义有明确类型。普通值和 `env` 引用使用不同 JSON 形态。密钥只接受引用 |
| HTTP 请求 | `method` 与 `url` 或 `path` 二选一，`path` 组合所选环境 `baseUrl`。`query` 和 `headers` 为有序键值对数组。`body` 包含类型和内容。`timeoutMs` 为可选正数 |
| MCP 连接与请求 | `mcp.transport` 为 `stdio` 或 `streamableHttp`。stdio 需 `command`，可含 `args`、`cwd`、`env`。HTTP 需 `url`，可含 `headers`。工具调用包含 `tool` 和对象 `arguments` |
| 批次文件 | `schemaVersion` 与 `steps`。每步含 `id`、`type` 及该类型的参数。可用 `extract` 将成功结果写入后续步骤变量。遇到错误停止，保留前面结果。每步的输入和错误从对应步骤读取 |

### 9.2 执行记录

运行状态为 `running`、`passed`、`failed`、`canceled`、`interrupted` 和 `unknown`。开始和每步结束写库。重启发现未结束的运行时，准备阶段标中断，若写操作已经发出且没有结果则标未知。CLI 与界面保留原编号并可查询。取消仍在运行的请求或会话时回写本机实际结果和连接状态。记录结果、目标别名、用例版本、已执行及跳过步骤和原错误。报告支持 JSON，CLI 输出结构与文件报告一致。首版历史默认按最近优先，可按类型和结果筛选，允许按用户给定日期清理。

## 10. Wiki

- 生成基于已完成的全量或增量扫描快照。预览显示使用的快照、输出语言、目标目录、能力条数、缺失来源及改动的页面。快照不完整时要求明确选择可用的上次快照。
- 落盘输出 `README.md`、`api/`、`mcp/`、`skills/`、`catalog.json` 和生成文件清单。标题使用选定语言，原始 API 名、参数、技能正文及人工说明保留原文。每页由稳定 ID 派生文件名，写项目相对来源路径、定义摘要和调用示例。目录用相对链接，不依赖一级部署 URL。
- 人工说明放 `wiki-notes/<稳定ID>.md`。生成时按 ID 附加到页面。删除能力后，源人工文件保留并在预览列出。过往生成的文件可依据清单更新。自选目录内的外部文件不在替换范围，若目标冲突则指出文件路径。
- `catalog.json` 包含 `schemaVersion`、快照引用、导出语言和 `items`。每条给出能力 ID、类型、名称、摘要、来源文件、可选定义路径和 Wiki 页路径。机器可读文件使用 UTF-8，键名独立于界面语言，无秘密、用户私有绝对路径、原始认证内容。可从 UI 下载，也可以 CLI 生成。
- 相同输入和语言产生相同正文与路径。构建到临时目录后做链接检查再原子切换工作台默认输出。自选导出目录只更新清单内的归属文件，失败时不登记为成功。首版通过工具自身浏览 Markdown，导出的文件可用普通 Markdown 工具打开。

## 12. 完整 CLI

### 12.1 命令表

CLI 入口名为 `ifg`，在 `package.json` 的 `bin` 中注册。通用参数包括 `--project <路径>`、`--json`、`--help` 和 `--version`。所有命令均可从项目目录运行，也可由其他目录选择项目。下表是首版公开命令的范围。

| 任务 | 命令 | 结果和输入 |
| --- | --- | --- |
| 启停与状态 | `start`、`status`、`stop` | `start` 支持 `--no-open`、`--port`、`--foreground`；状态包括实例、实际 URL、项目路径和库位置 |
| 配置 | `config show`、`config validate --file`、`config apply --file` | 查看当前有效配置和来源，验证或更新本机配置。支持设置语言和扫描范围 |
| 环境及连接 | `profile list`、`profile show <id>`、`profile put --file`、`profile remove <id>` | 环境、地址、Header 引用、启动程序和 MCP 连接配置，输出将密钥值掩码 |
| 扫描和历史 | `scan`、`scan list`、`scan show <id>`、`scan diff --from --to` | `scan` 支持 `--full` 和 `--include-untracked`；返回扫描快照、诊断及可比较状态 |
| 目录 | `catalog search <query>`、`catalog list`、`catalog show <id>`、`source show --path` | 支持类型、服务和分页，能看到稳定 ID、定义、差异及源码范围。源码只读 UTF-8 项目文件 |
| HTTP 发现和调试 | `api import --file` 或 `api import --url`、`api send --file`、`api curl --file`、`api export <id>` | 导入 OpenAPI、从模板执行请求、导出脱敏 cURL 和契约片段；运行地址及变量取所选环境 |
| MCP 发现和操作 | `mcp discover --profile`、`mcp call <tool> --profile --args`、`mcp read <uri> --profile`、`mcp prompt <name> --profile --args` | 查工具、资源、提示词及模板，调用工具、读取资源、获取提示词。执行可直接返回和写入读取记录 |
| MCP 连续操作 | `mcp batch --profile --file` | 文件含顺序动作 `discover`、`call`、`read`、`prompt`。同一连接依次执行，完成后关闭；可含后续步骤的输入提取与引用 |
| 技能 | `skill list`、`skill search <query>`、`skill show <id>` | 返回列表、Markdown 正文、相对路径及引用。需要引用正文时使用 `source show` |
| 用例与套件 | `case list|show|put|remove|export`、`suite list|show|put|remove|export` | `put` 接收用例或套件文件；全部操作以稳定 ID 定位；导出内容可再次导入 |
| 执行和报告 | `test run --case` 或 `test run --suite`、`run list`、`run show <id>`、`run cancel <id>`、`run export <id>` | 可用 `--profile` 显式覆盖本次环境。执行中可 Ctrl+C，也可由另一端按原运行编号请求取消 |
| Wiki | `wiki preview`、`wiki build`、`wiki list`、`wiki show <id>`、`wiki note-put <id> --file` | 预览和生成支持 `--snapshot`、`--out`、`--lang`；可查导出及单页，按 ID 写入人工注释 |
| 本地维护 | `data backup --out`、`data restore --file`、`data prune --before` | 恢复覆盖用 `--replace`；清理默认先列范围，`--apply` 执行；日期为 ISO 8601 |
| 给 AI 的契约 | `commands --json`、`schema <name>` | `commands` 输出命令、参数、是否写入和示例；`schema` 打印 config、settings、profile、request、mcp-batch、case、suite、catalog、result 等 JSON Schema |

Web 和 CLI 使用同一套持久化设置。已运行的任务由实际执行该任务的进程持有。跨进程取消用运行记录写入取消请求，执行进程在运行期间检查并确认结果。进程不可达时查询仍能得到最后记录，下一次初始化根据执行阶段标记中断或未知。无需系统级任务服务。

### 12.2 输入和机器可读输出

- `--json` 成功或失败都在 stdout 输出一份 UTF-8 JSON 对象，且结尾换行。进度和诊断日志走 stderr。CLI 的 `--help` 输出人类读得懂的用法，给 AI 的命令表由 `commands --json` 提供。前台 Web 启动时只输出一次启动结果，后续服务日志走 stderr 或本地日志。
- 接收 JSON 的 `--file` 和 `--args` 支持路径，值 `-` 表示从 stdin 读取一份 JSON。MCP `--args` 也接受以内联 JSON 传值。配置、用例和套件的导入符合对应 Schema。AI 遇到字段不确定时，可先调用 `schema`。
- 输出外层固定含 `schemaVersion`、`ok`、`command`、`data`、`error`。错误包含 `code`、`message`、`details`。错误码及键名保持英语固定形式，状态和发现来源有固定枚举。列表返回 `items`、`limit`、`offset`、`total`。进一步查询使用记录 ID，避免从表格文字提取。
- 命令默认交互提示关闭，帮助、预览和校验类命令可用于执行前准备。CLI 的调用、写入和清理按所给命令和显式参数执行。结果仍保留在同一项目的历史。API/MCP 密钥传引用，机器输出不携带秘密。
- `scan` 部分成功时保留诊断，`--require-complete` 将部分结果视为环境或操作失败。相同运行编号可通过 `run show` 查询。断言失败时仍返回完整报告数据。
- `schema` 的普通输出是原始 Schema JSON，方便直接重定向为文件。传 `--json` 时返回标准外层对象。

| 退出码 | 含义 |
| --- | --- |
| 0 | 命令完成，若为测试则断言全部通过 |
| 1 | 目标返回且用例断言失败 |
| 2 | 命令、参数、输入格式或项目配置不合法 |
| 3 | 目标不可用、数据库忙、权限不足或当前操作无法完成 |
| 4 | 任务已中断、取消或结果未知，详情区分具体状态 |

~~~json
{
  "schemaVersion": 1,
  "ok": true,
  "command": "catalog search",
  "data": {
    "items": [{"id": "api:task-api:get:/tasks/{id}", "kind": "api", "name": "GET /tasks/{id}"}],
    "limit": 20,
    "offset": 0,
    "total": 1
  },
  "error": null
}
~~~

### 12.3 AI 调用示例

~~~bash
ifg commands --json
ifg schema case
ifg scan --project . --require-complete --json
ifg catalog search task --kind api --limit 20 --json
ifg mcp discover --profile sample-stdio --json
ifg mcp batch --profile sample-stdio --file mcp-sequence.json --json
ifg skill search summary --json
ifg case put --file get-task.json --json
ifg test run --case get-task --profile demo --json
ifg run show <run-id> --json

~~~

这些操作从未启动 Web 的干净环境也能使用。发布包附 `docs/cli.md`，用一条命令演练每类操作，并维护 JSON 示例。UI 的每项持久化设置、查看、编辑、测试、取消和导出都需在命令表中找到对应操作。源码打开在 CLI 以显示路径或读取正文实现。

## 13. 本机 Web 接口

Web 接口与 CLI 共用输入 Schema、错误码和服务。浏览器以 `/api/v1` 下的本机接口通信。下表列逻辑路由，发布包对其内部用途负责。给自动化用户的稳定入口是 CLI 和导出格式。

| 路由组 | 行为 |
| --- | --- |
| `GET /project`，`GET/PUT /config`，`/profiles` | 读取当前项目，读写工具自身配置和环境 |
| `POST /scans`，`GET /scans/{id}`，`GET /catalog`，`GET /catalog/{id}` | 扫描、诊断、分页和能力详情 |
| `GET /sources`，`GET /skills/{id}` | 读取项目内源码及技能正文 |
| `POST /runs`，`GET /runs/{id}`，`POST /runs/{id}/cancel` | 请求、协议任务或套件执行。长任务返回运行编号 |
| `/mcp/connections`，`/cases`，`/suites` | 连接的建立、查询和关闭、用例与套件的常规管理 |
| `POST /wiki/preview`，`POST /wiki/build`，`GET /wiki/{id}`，`PUT /wiki/notes/{id}` | 生成、查看与写入说明 |
| `/data`，`/instance` | 本机清理、备份、恢复和当前实例操作 |

本机 API 错误体沿用 `{code,message,details}`。HTTP 4xx 用于本机输入、找不到、冲突或环境配置问题，HTTP 5xx 用于工作台自身故障。目标 API 的 4xx/5xx 放进实际执行结果，保留原状态与正文。读源码接口用项目相对路径，写入类型按功能受限。

开发过程中同步编写并运行与当前改动相关的单元测试。单元测试至少覆盖项目根解析和配置校验、扫描及合并、HTTP 请求模板和断言、MCP 结果和会话状态处理、SQLite 数据操作、CLI JSON 与退出码、双语键和 Wiki 合并规则。实现时可用局部冒烟验证接口和依赖。所有功能接通后再集中运行全量单元测试、真实本机协议集成、跨操作系统启动和 UI/CLI 共用数据的端到端测试。修复发现的问题后重跑受到影响的检查。

模拟测试用于注入故障，结果标明模拟。发布验收记录 OS、运行时、版本、命令、结果摘要和证据路径。综合测试优先在当前 Windows 机器跑通并给出可直接启动的本地版本。其他平台缺少测试环境时保留对应验收待办，并如实标明实际支持证据。
