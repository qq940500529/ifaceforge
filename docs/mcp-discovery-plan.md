# MCP 能力发现方案

**实施方案** · 覆盖源码扫描、隔离临时运行和本机临时运行 · 桌面与 CLI 共用实现

## 1. 产品行为

| 入口             | 何时使用                                                  | 能取得什么                                                                     |
| ---------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **扫描源码**     | 添加项目、扫描工作区、切换到选定的 Git 提交或比较两个版本 | 仓库声明、源码注册位置、可静态确定的能力和参数、同一版本携带的能力清单         |
| **隔离发现能力** | 需要核对服务实际公布的清单，有兼容容器或虚拟机            | 执行仓库入口，记录协议协商结果、四类能力、实际 Schema 和清理状态               |
| **本机临时发现** | 服务依赖系统组件或本机开发环境                            | 通过选定仓库的实际启动入口运行新实例，读取当前环境下公布的能力，随后关闭该实例 |

普通扫描自动读取源码和声明。需要运行时，工作台优先展示隔离发现。本机临时发现是单独入口，必须由人或获得明确执行授权的 CLI 选择本机方案。每个运行计划绑定项目、代码版本、入口、执行环境和操作，环境不可用时保留静态结果并显示具体原因。

三种入口共用服务详情。发现操作读取服务身份、声明的客户端可见能力，以及工具、资源、资源模板、提示词四类分页清单。调用工具、读取资源正文、实例化并读取资源模板和获取提示词仍从测试入口触发，并显示具体目标及参数。

## 2. 源码扫描

### 读取与解析

1. 从启动配置、语言依赖清单及锁文件、项目入口、能力清单建立候选服务。支持 `.mcp.json`、`.vscode/mcp.json` 及可识别的 JSONC、TOML、YAML 配置，读取 `mcpServers`、`servers` 和对应 TOML 表。把仅有地址的配置展示为服务声明。用配置路径和服务标识匹配注册记录，多服务仓库中保留暂时无法归属的条目。
2. 复用 TypeScript／JavaScript 的 Babel 解析器和现有 Python 解析能力。其余语言使用随应用分发的固定版本语法解析器。语言适配器提取导入及别名、接收对象、注册调用、装饰器或注解、常量和简单字符串拼接。按入口追踪当前代码版本中可见的注册函数、模块和表驱动注册。扫描期间仅读取文件和语法树。
3. 提取名称、URI、URI 模板、说明、参数、可解析的输入输出 Schema、源文件和行号。记录 SDK、适配器版本及缺失字段。运行时生成的名称、条件注册、外部数据或自定义 Schema 钩子按条目标明原因，自定义注册封装可添加项目级声明式规则。
4. 已提交的 `mcp-capabilities.json` 按服务和 Git 版本读取。建立可选的 CI 导出流程，用仓库真实注册入口生成清单并检查更新。原始声明、静态推断和实测结果都可查看，字段出现差异时提供对比。
5. 扫描只处理当前工作区或用户选择的提交。分支选择器和 Git 图仅读取元数据，对比时最多补扫两个端点。按文件内容及解析规则缓存语法结果，对大文件、深依赖链、条目数和超时显示明确诊断。任务进度、取消和错误详情共用现有扫描弹窗。

语法解析器提供语言结构，各适配器负责识别具体 MCP 注册契约。兼容矩阵按语言、SDK／框架及版本记录已验证的注册写法。 [Tree-sitter 解析器文档](https://tree-sitter.github.io/tree-sitter/using-parsers/index.html) · [MCP SDK 列表](https://modelcontextprotocol.io/docs/2026-07-28/sdk)

| 源码语言范围                                                                         | 实现及验收                                                                                                                                |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript、JavaScript（含 Node.js、Deno、Bun 项目）、Python                         | 覆盖主流 MCP SDK 和 Python FastMCP 的常见注册方式，验证旧版与新版 SDK、入口追踪、跨模块常量和常见类型定义。                               |
| Go、Rust、Java、Kotlin、C#、F#、C、C++、Swift、Ruby、PHP、Scala、Dart                | 为每种语言交付语法适配和经测试的注册规则。优先识别其 MCP SDK 的公开注册入口，其余以可定位的 JSON-RPC 方法表、声明结构或项目配置作为证据。 |
| Bash／Shell、PowerShell、批处理、Lua、R、Julia、Elixir、Erlang、Haskell、OCaml、Perl | 支持相应的启动声明、可识别的注册表和内嵌 JSON-RPC；逐语言用仓库样例验证能读到哪些字段。                                                   |
| 其他语言和私有框架                                                                   | 可通过通用清单、项目规则、JSON-RPC 注册线索和两种临时运行方式接入。只定位到协议方法时，界面显示服务线索与源位置。                         |

## 3. 隔离临时运行

- **Linux 容器**。复用现有 Docker 方案，在 Windows、macOS、Linux 使用可用的 Linux 容器引擎。按提交导入只读源码，使用隔离网络、非特权身份、临时可写目录和资源上限。预览中显示镜像标识、运行时、命令、参数、工作目录和注入变量名。依赖事先在指定镜像中准备，或由项目声明并预览一项独立的依赖准备操作。
- **启动配置**。允许同一服务为原生宿主与 Linux 容器分别提供命令。原样解析各方案，`powershell.exe` 保留为 Windows 入口。原生 macOS 依赖列入本机临时运行的验证矩阵，Linux 兼容服务可在 macOS 的 Linux 容器里隔离发现。
- **资源回收**。给启动、就绪、协议协商、分页设置各自时限。结束时先关闭会话，再回收本次容器。成功、部分成功、取消、超时和应用退出都纳入回收流程；应用重启时检查记录中的专属实例。能力结果和清理结果分别落库。

## 4. 本机临时运行

直接在 Windows、macOS 或 Linux 使用仓库正式入口。对已经安装的 语言运行时、系统组件和本地设置，只在与启动计划匹配时使用。每次显示精确的可执行文件路径、参数、代码来源、工作目录、环境变量名、选中的本机配置及测试操作。历史提交使用本次运行的临时源码目录，执行前复核命令和源码指纹。当前工作区方案记录实际源码版本和工作区状态，变化后重新生成预览。

启动器按可执行文件和参数启动，只有计划明确选择脚本解释器时才经该解释器执行。Windows 使用隐藏控制台的进程托管和 Job Object，macOS／Linux 使用专属进程组监督。HTTP 启动方案使用专属回环端口和就绪检查，发现端口已被占用时显示冲突。对守护化或复用系统服务的入口显示其生命周期约束，退出后核对本次可追踪的子进程及监听端口。已在运行的其他用户进程保留原有生命周期。 [Microsoft Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

本机模式继承运行账户可用的文件、网络与应用权限，启动脚本可以产生副作用。默认传递最小运行环境，额外 PATH、配置和凭据由用户在方案中明确选择，日志和导出脱敏。成功或失败都先尝试正常退出，超时再结束本次进程组。系统服务、外部系统写入或应用启动的独立进程有自身生命周期，发现结果中明确显示仍待处理的资源。

## 6. 界面、CLI 和记录

- **桌面**。MCP 页延用列表和详情布局，提供来源筛选、状态提示和三种发现入口，详情展示 Schema、代码位置、版本、发现时间与运行环境。依据顶栏当前 Git 版本加载记录，运行计划在执行前确认。任务小窗显示准备、启动、协商、分页、清理阶段，可取消、查看和复制诊断。长列表独立滚动，桌面宽屏下详情留在可视区，窄窗打开详情后返回原列表位置。
- **CLI**。保留 `mcp targets / plan / probe / inventory / call / read / template / prompt / batch`，增加 `--mode isolated|native` 和 `--protocol auto|VERSION`，兼容现有隔离调用默认值。源码入口用现有 `scan`、`catalog` 和 `compare`，`mcp inventory` 可按来源读取。自动化先用 `plan --json` 获取命令、权限要求、稳定错误码和指纹，再以 `probe --approve FINGERPRINT --async --json` 发起任务，随后查询状态或取消。CLI 指南提供可直接使用的命令顺序、JSON 字段、退出码和到期后重新规划的处理方式。
- **数据**。每条能力记录关联项目、服务、来源、代码版本、运行计划、实际协议、发现时间和分类状态。实际发现、已提交清单及静态结果可按字段比较和导出。缓存以版本与环境为范围，部分发现保留本次结果并可查看上次完整记录。隔离与本机结果可并列核对，原始敏感配置及环境值留在本机凭据存储。

## 7. 开发和验收

开发时随改动补齐并运行针对性单测。源码引擎、运行器、协议、桌面和 CLI 接通后集中做一次综合验收，修复后做必要复测。验收通过后再出包、发布 GitHub，并按测试证据更新兼容矩阵、开发指南、桌面手册及 CLI 的 AI 调用指南。

| 验收项     | 通过条件                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 源码准确性 | 使用多个相互独立的公开测试项目，逐项核对源码识别出的名称、URI 和参数字段。运行时生成的字段以临时发现的 Schema 为基准。                                             |
| 多语言     | 对语言表每种语言验证入口、注册、源位置、可确定字段及未识别情况；多服务仓库验证同名能力归属。覆盖条件注册、常量拼接、改名、无关同名调用、截断文件和动态 Schema。    |
| 真实入口   | Windows、Linux 和 macOS 使用测试项目各自的原生启动入口。检查完整生命周期、缺失配置诊断和能力清单。                                                                 |
| 协议和能力 | 逐个已列版本和适用传输完成协商测试，验证生产 SDK 与历史协议样例、四类列表与测试动作、含多页及重复游标、权限错误、部分成功、不支持能力和旧版 stdio 提前退出并重启。 |
| 关闭和复现 | 验证成功、失败、超时、取消、重启清理，检查进程、专属端口、容器。验证工作区变更触发重新规划，三种结果来源与不同项目记录互不串用。                                   |
| 桌面和 CLI | Windows 实际窗口逐按钮操作，检查展开／收起、复制诊断、长列表和窄窗、多个操作组合、切项目、切 Git 版本、测试与历史。CLI 对照执行同一批流程及 JSON 错误路径。        |
| 发布       | 保存公开测试样例和各平台构建与实测范围，更新 GitHub 工作流、兼容矩阵及中英文手册，保留 MIT 许可证和数链创元（天津）信息技术有限责任公司版权声明。                  |
